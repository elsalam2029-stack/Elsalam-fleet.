# نظام أسطول شركة السلام — حزمة الملفات

## محتويات الحزمة
- `index.html`: واجهة النظام الحالية. النسخة الحالية تعتمد على التخزين المحلي في المتصفح، ولا تتزامن تلقائيًا بين أجهزة الشركة.
- `database/alsalam_fleet_schema.sql`: إنشاء جداول وقواعد البيانات.
- `database/alsalam_fleet_seed.sql`: بيانات مرجعية أولية مستخرجة من النموذج؛ راجعها قبل تشغيلها في الإنتاج.
- `api/`: بداية خادم Node.js/Express مع فحص اتصال PostgreSQL، وإعدادات أمان أساسية.

## مهم جدًا قبل استخدامه داخل الشركة
هذه الحزمة ليست نظامًا مكتملًا جاهزًا للإنتاج بنسبة 100%، ولم يتم نشرها أو اختبارها على خادم الشركة. واجهة `index.html` الحالية لم يتم ربطها بعد بواجهات API، كما أن نقاط API الخاصة بتسجيل الدخول والصلاحيات والعمليات اليومية غير مكتملة. لا تستخدمها كقاعدة بيانات مشتركة بين الموظفين قبل إكمال الربط والاختبارات.

## أين ترفع الملفات على GitHub؟
لا ترفع كل الملفات داخل مجلد `.github`؛ هذا المجلد مخصص عادةً لسير العمل والإعدادات. ضع `index.html` في جذر المستودع حتى يعمل GitHub Pages. ارفع مجلدي `api/` و`database/` إلى جذر المستودع أيضًا، أو إلى المستودع الخاص بالخادم.

## إعداد قاعدة البيانات
1. أنشئ قاعدة PostgreSQL مستضافة مع نسخة احتياطية مفعّلة.
2. نفّذ `database/alsalam_fleet_schema.sql` أولًا من خلال أداة SQL الخاصة بقاعدة البيانات.
3. راجع `database/alsalam_fleet_seed.sql` وتأكد من صحة البيانات وعدم وجود بيانات تجريبية غير مناسبة، ثم نفّذه عند الحاجة فقط.
4. احتفظ بسلسلة الاتصال في إعدادات البيئة لدى مزود الخادم؛ لا تضع كلمة المرور في GitHub أو داخل `index.html`.

## تشغيل واجهة API محليًا للاختبار
1. ثبّت Node.js 20 أو أحدث.
2. افتح الطرفية داخل مجلد `api` وشغّل `npm install`.
3. انسخ `.env.example` إلى `.env` وأدخل `DATABASE_URL` الصحيح. لا ترفع ملف `.env` إلى GitHub.
4. شغّل `npm start`.
5. افتح `/api/health` على عنوان الخادم؛ يجب أن يعرض `ok: true` و`database: connected`.

## ما يلزم قبل التشغيل الفعلي
- إكمال وربط جميع عمليات الواجهة بقاعدة PostgreSQL بدل `localStorage`.
- إضافة تسجيل دخول آمن وجلسات أو رموز موثوقة، وصلاحيات لكل دور، وحماية لكل نقطة API.
- التحقق من صحة المدخلات، ومنع التكرار، وسجل تدقيق، واختبارات للحسابات والتقارير.
- اختبار النسخ الاحتياطي والاستعادة، وHTTPS، ومراقبة الأخطاء، وإدارة أسرار الخادم.
- تجربة قبول فعلية مع بيانات منسوخة/اختبارية قبل نقل بيانات التشغيل الحقيقية.

**تنبيه:** لا تُشغّل ملف SQL الخاص بالبيانات المرجعية على قاعدة تحتوي على بيانات الشركة قبل مراجعة نسخة احتياطية ومراجعة محتواه.
